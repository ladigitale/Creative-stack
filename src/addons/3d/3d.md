# 3D

`sonic-3d` — viewer **Three.js** (glTF / GLB), caméra orbit / perspective / ortho, outputs dataProvider paresseux.

Import opt-in (hors bundle `functional`) :

<sonic-code language="javascript">
  <template>
import "@supersoniks/creative-stack/3d";
import type {
  Sonic3dConfig,
  Sonic3dOutput,
  Sonic3dAsset,
  Sonic3dCameraMode,
} from "@supersoniks/creative-stack/3d";
  </template>
</sonic-code>

CDN (after the core): `creative-stack-3d.bundle.js` — see [CDN addons](#docs/_getting-started/cdn-addons.md/cdn-addons).

## Démo (modèle CDN)

`DamagedHelmet` (Khronos, jsDelivr). Orbit · zoom · pan · survol highlight · pick · double-clic = recentrer. Sans `src` : cube de démo. Molette : zoom tant qu’il reste de la marge ; aux bornes `minDistance` / `maxDistance`, le scroll page reprend.

## Form auto-bind (`formDataProvider`)

Comme `sonic-shader` : si `dataProvider` (ou un ancêtre `formDataProvider`) contient des champs aux **mêmes noms** que l’API, ils pilotent le viewer sans JS.

| Champ form | Effet |
|------------|--------|
| `src` / `asset` / `glb` | charge le modèle (`glb` = GLB base64, sans réseau) |
| `nodes` | surcharges de nœuds en direct (voir ci-dessous) |
| `camera` | mode caméra |
| `fov` / `exposure` | optique |
| `autoRotate` | rotation orbit |
| `minDistance` / `maxDistance` | bornes zoom orbit |
| `minPolar` / `maxPolar` | bornes verticale (degrés) |
| `yaw` / `pitch` / `distance` | position orbit sphérique |
| `lookAt` | `[x, y, z]` : point visé ; la caméra y glisse quand il change (suivre un joueur, la balle), le glisser de l'utilisateur reste sinon |

Conseil : séparer `out-data-provider` du form. Les entrées pures (`fov`, `exposure`, `autoRotate`, `src`…) ne sont jamais réécrites en out sur un DP partagé. `yaw` / `distance` / `pitch` restent publiables ; un changement manuel d’orbit coupe `autoRotate`.

Gate paresseuse : un `sonic-input name="yaw"` **ne** déclenche **pas** la publication out (seul un lecteur sur `ready` / `frame` / `cam*` / `hit*`… le fait).

## Scène pilotée par les données (`glb`, `nodes`, `target`)

Pour des jeux / scènes interactives sans JS : le modèle est embarqué, les nœuds sont animés depuis le DP, les taps reviennent au store.

```json
{ "tagName": "sonic-3d",
  "attributes": { "dataProvider": "game", "target": "game", "pick": true,
                  "pick-names": "^(m_|hole_)", "min-polar": "0.6", "max-polar": "1.25" } }
```

DP `game` (publié par le reducer du store) :

```json
{ "glb": "<base64>",
  "nodes": {
    "m_24": { "visible": false },
    "m_10": { "x": 0, "z": 0, "lift": 0.9, "ease": { "ms": 320, "curve": "inOut" } },
    "hole_24": { "emissive": 1, "emissiveColor": "#ffb347" } } }
```

- **GLB** : utiliser un GLB (les buffers `data:` à l'intérieur d'un glTF JSON passent par `fetch`, non supporté). Changer `glb` recharge la scène : surcharges, caches et clones de matériaux sont purgés.
- **`nodes`** : résolution par `getObjectByName` (mise en cache). Champs : `x y z`, `rx ry rz` (radians), `scale` (nombre ou `[x,y,z]`), `visible`, `color`, `emissive` (intensité) + `emissiveColor`, `opacity`, `ease {ms, curve: linear|in|out|inOut}`, `lift` (arc en y, requiert `ease.ms`). Sémantique **patch** : champs absents inchangés, nœuds absents non réinitialisés ; `"$reset": true` remet tout dans l'état du fichier. Les matériaux sont clonés au premier override de `color` / `emissive` / `opacity`. ≤ 200 nœuds par mutation. Republier la même valeur ne fait rien. Les interpolations passent par la boucle de rendu existante (sans boucle active, appliqué sans `ease`). Les couleurs ne sont pas interpolées. Noms inconnus ignorés, comptés dans la sortie `nodesMissing`.
- **Tap** : émis au `pointerup` si le pointeur a bougé de < 6 px en < 400 ms (un drag d'orbite n'envoie rien). Les nœuds `visible:false` ne sont pas pickables. `pick-names` filtre **le raycast** (nœud ou ancêtre dont le nom matche) : un nœud décoratif (table, plateau…) devant la cible est transparent au tap. Avec `target`, aucun surlignage bleu au survol : l'apparence est pilotée par le store (`nodes`). L'événement DOM `pick` (pointerdown) est conservé.
- **Glisser (monde)** : `drag=".*"` (regex des instances) rend les objets d'un `monde` déplaçables au pointeur : l'objet saisi suit le pointeur, rangé en direct (appui selon sa nature, aimantation aux murs et aux voisins, place libre la plus proche), l'orbite est suspendue pendant le geste. Au lâcher : action `{type: "place", payload}` vers `target`, évènement DOM `place`, clé de sortie `placed`. Un simple tap reste un tap. Voir monde.md, « Édition ».
- **Matériaux procéduraux** : un matériau glTF nommé `tex:wood`, `tex:felt`, `tex:marble` ou `tex:noise` reçoit une texture générée en canvas (sans image ni réseau). `baseColorFactor` (ou `color` en override) la teinte. Sans `TEXCOORD_0` dans le glb, les UV sont générés (sphériques pour `marble`, planaires XZ sinon) : un glb sans UV est nettement plus léger. Primitives sans `NORMAL` : ombrage à facettes.
- **Lumières** : un glb qui contient des lumières (`KHR_lights_punctual`) remplace l'éclairage par défaut de la scène (ambiance, couleur, intensité à décrire dans le glb).
- **Base64 à la main** : éviter les longues séquences répétitives dans le glb (une recopie par un agent y perd ou duplique des caractères et corrompt le fichier) ; garder le glb petit (UV générés, peu de sommets).

## Sortie / dataProvider

Entrée : champs ci-dessus, plus `play` (booléen, boucle de rendu) et `damping` (0–1, inertie de l'orbite) ; une clé du DP l'emporte sur l'attribut. Sortie (`Sonic3dOutput`) : `status` / `error` / `cam*` / `target*` / `distance` / `yaw` / `pitch` / `pointer*` / `ready` / `hit*`… With `frame-out` (or a listener on `frameUrl` / `snapshot`): lazy JPEG canvas capture → `frameUrl` + `snapshot` (`SonicMediaRef`). Event `out`. Publication **paresseuse**.

### État standard (`status` / `error`)

| `status` | Quand |
|---|---|
| `idle` | Pas encore de rendu (avant le premier chargement) |
| `loading` | Chargement du modèle (`src`, `asset`, `glb`) en cours |
| `ready` | Scène prête (modèle, cube de démo ou scène vide) |
| `error` | Échec : modèle introuvable, format refusé, GLB trop gros ou invalide, WebGL indisponible. `error` porte le message (aussi affiché dans le viewer et dans l'event `error`) ; sinon `error: null` |

Contrairement à la télémétrie (paresseuse, cadencée par la boucle de rendu), `status` et `error` sont écrits **à chaque transition** dans `out-data-provider`, même sans lecteur : un échec de chargement arrête la boucle, il serait sinon perdu. `ready` / `loading` (0|1) restent publiés comme avant.

```json
{ "tagName": "sonic-3d", "attributes": { "src": "/modeles/plateau.glb", "dataProvider": "vue", "out-data-provider": "vueOut" } },
{ "tagName": "sonic-if", "attributes": { "dataProvider": "vueOut", "key": "status", "equals": "error" },
  "nodes": [ { "tagName": "sonic-value", "attributes": { "dataProvider": "vueOut", "key": "error" } } ] }
```

## Caméras

| `camera` | Usage |
|----------|--------|
| `orbit` (défaut) | Produit / modèle isolé — orbit + pan, polar limité |
| `perspective` | Scène libre + pan |
| `ortho` | Plans techniques / UI 3D |
| `map` | Vue de carte / jeu vu du dessus : glisser = se déplacer sur le sol, pincer / molette = zoom, pas de rotation (combiner avec `min-polar` / `max-polar` bas et `lookAt`) |

## Asset neutre (HF plus tard)

```ts
type Sonic3dAsset = {
  kind?: "gltf" | "glb" | "obj" | "ply" | "url";
  url?: string;
  blob?: Blob;
};
```

Le viewer lit `asset` ou `src` depuis le DP — la source (fetch, upload, HF) n’est pas couplée.

## Attributs

| Attribut | Rôle |
|----------|------|
| `src` | URL glTF / GLB (vide → démo) ; accepte aussi `data:model/gltf-binary;base64,…` |
| `glb` | GLB en base64, décodé puis `GLTFLoader.parse` — **aucun `fetch`** (compatible CSP `connect-src` stricte). Prioritaire sur `src` |
| `max-glb-bytes` | Plafond du GLB décodé (défaut 512 Ko, plafond dur 2 Mo) |
| `target` | Id d'un `sonic-store` : un **tap** sur un objet envoie `{type, payload:{objectId,x,y,z}}` (requiert `pick`) |
| `pick-action-type` | Type d'action envoyé à `target` (défaut `pick`) |
| `pick-names` | Regex sur le nom du nœud ; les autres sont ignorés (ex. `^(m_\|hole_)`) |
| `pick-empty` | Tap dans le vide / sur un nœud filtré → `{objectId:null}` (désélection) |
| `camera` | `orbit` \| `perspective` \| `ortho` \| `map` |
| `fov` | FOV perspective (défaut 45) |
| `exposure` | Tone mapping (défaut 1) |
| `min-distance` | Zoom orbit mini (défaut 0.5) |
| `max-distance` | Zoom orbit maxi (défaut 50 ; `0` = ∞) |
| `min-polar` / `max-polar` | Angle vertical en **degrés** (défaut 8–172) |
| `auto-rotate` | Rotation orbit |
| `gestures` | `auto` (défaut : coopère avec le défilement si la scène est dans une page ou une zone qui défile : un doigt vertical et la molette font défiler, Ctrl / ⌘ ou pincement pour zoomer), `capture` (la scène prend tout : jeux plein écran), `cooperative` |
| `fit` | Fit bbox après load (défaut true) ; tout le contenu tient dans le cadre, en largeur aussi sur un écran en portrait |
| `pick` | Survol highlight + clic → event `pick` + `hit*` ; double-clic = fit |
| `play` / `play-on-hover` | Boucle RAF |
| `play-offscreen` | Garde RAF / runtime hors viewport (pont live `#id`) |
| `release-offscreen` | Dispose renderer hors viewport (défaut true) sauf si `play-offscreen` / consommateur live |
| `damping` | Inertie OrbitControls (défaut `0.08`, `0` = off) |
| `dpr-max` | Cap devicePixelRatio (défaut 2) |
| `dataProvider` / `out-data-provider` | Entrée / sortie |
| `out-interval` | Throttle publication ms (défaut 80) |
| `frame-out` | Publishes `frameUrl` + `snapshot` (canvas JPEG) for shader chaining |
| `snapshot-interval` | Canvas capture throttle ms (default 250) |

## Shader bridging

No shared WebGL context between `sonic-3d` and `sonic-shader`.

| Need | Bridge |
|------|--------|
| **Live post** | `channel0="#plateau"` on `sonic-shader` (or DP `{ element }`) — canvas copy each frame via `SonicFrameSource` |
| **Export / HF / freeze** | `frame-out` → `frameUrl` + `snapshot` (`SonicMediaRef` JPEG). Clone with `cloneMediaRef` before holding a frame |

```html
<!-- Live -->
<sonic-3d id="plateau" play auto-rotate …></sonic-3d>
<sonic-shader channel0="#plateau" image="…" play></sonic-shader>

<!-- Export / freeze -->
<sonic-3d frame-out out-data-provider="view3d" snapshot-interval="250" …></sonic-3d>
```

Demo: [Visual stack — 3D → shader live](#docs/_misc/visual-stack.md/visual-stack).

Un `sonic-shader` / `sonic-webgpu` qui pointe `#id` s’enregistre via `registerFrameConsumer` : le 3D **continue hors viewport** (pas de dispose). Option explicite : `play-offscreen`.

### Arrêt net

`el.stopMotion()` coupe `autoRotate` et l’inertie OrbitControls. Quand la caméra est immobile depuis ~8 frames : event `rest` + champ out `moving: 0|1`. Attribut `damping` (défaut `0.08`, `0` = off).

## Post FX (in-viewer)

When `post-image` is set, the scene renders to an offscreen target with a **depth texture**, then ShaderToy-style passes run inside the same Three context (`post-buffer-a`…`post-image`). Same GLSL as `sonic-shader` (`mainImage`, `iChannel0–3`, `uParam0–3`, `sonicLinearDepth`).

| Channel token | Source |
|---------------|--------|
| `scene` (default ch0) | Color render target |
| `depth` | Depth texture from the scene pass |
| `buffer-a`…`d` | Ping-pong buffers |
| URL / `#id` | External texture (same as shader live bridge) |

```html
<sonic-3d
  post-image="…GLSL…"
  post-image-ch0="scene"
  post-image-ch1="depth"
  param0="0.5"
  post-scale="1"
></sonic-3d>
```

Demo: [Visual stack — post depth edges](#docs/_misc/visual-stack.md/visual-stack).

Pick / orbit still use scene geometry; `frame-out` captures the **final** canvas after post.

## Modèles de base (bibliothèque)

`src/addons/3d/library/` : petits modèles GLB prêts à l'emploi, générés sans asset tiers par `generate.mjs` (`yarn library:3d`, le spec compare le résultat aux fichiers commités). Chaque fichier est une enveloppe JSON `{format: "glb-base64", glb, bytes, nodes}` : **ranger `glb` dans un fichier `*.b64` de l'artefact** (`files`, 64 Ko max) et le référencer dans le DP du `sonic-3d` (`glb`). Les noms de `nodes` servent à `pick-names` et aux surcharges `nodes`. Disponibles :

- `3d/plateau-grille-5x5` : cadre en bois (`tex:wood`) et 25 cases `cell_<ligne>_<colonne>` ;
- `3d/pions-6` : `pion_0`…`pion_5`, une couleur chacun ;
- `3d/socle-vitrine` : `socle` + `anneau` doré, objet posé à y = 0.4.

Les copier en tronquant ou en retapant le base64 à la main le corrompt : le laisser passer tel quel (`save_resource` / `get_resource`). Un modèle ajouté ou modifié incrémente `version` ; il doit passer `base-library.spec.ts` (en-tête GLB, accesseurs, `GLTFLoader`, noeuds annoncés).

## Monde en primitives (`monde`)

Clé DP (ou attribut) `monde` : un monde complet décrit en JSON — modèles articulés faits de formes simples
(préréglages procéduraux `bipede`, `quadrupede`, `arbre`, `maison`…), clips d'animation, palette, textures
procédurales, placement d'instances pilotables et de décor semé. Les instances se pilotent par `nodes` comme des
nœuds glTF (`x y z rx ry rz`, `ease`, `lift`) avec en plus `clip`, `clipSpeed`, `clipT`, `roles`. Le même JSON et les
mêmes `nodes` donnent la même scène dans `sonic-2d`. Peut s'ajouter à un `glb` (le monde est monté dans le contenu
chargé). Format complet : [monde.md](monde.md).

## Réalité virtuelle et augmentée (`sonic-xr`)

`sonic-xr` ouvre une scène `sonic-3d` dans un casque (`immersive-vr`) ou en réalité augmentée sur téléphone ou casque à
passthrough (`immersive-ar`), par WebXR et `renderer.xr` de three.js. Rien à charger en plus : il fait partie de l'addon 3d.

```json
{ "tagName": "div", "nodes": [
  { "tagName": "sonic-3d",
    "attributes": { "id": "scene", "dataProvider": "jeu", "target": "jeu", "pick": true } },
  { "tagName": "sonic-button", "attributes": { "id": "vr", "type": "primary" },
    "nodes": [{ "tagName": "span", "attributes": { "text": "Entrer en VR" } }] },
  { "tagName": "sonic-xr",
    "attributes": { "id": "xr", "target": "scene", "for": "vr", "mode": "auto", "store": "jeu",
                    "features": "hand-tracking hit-test", "reticle": true } } ] }
```

- **Lancement** : le navigateur exige un geste. `for="vr"` ouvre (ou ferme) la session dans le clic ; `control`
  `{enter, exit, toggle, place}` (compteurs, forme `{n, mode: "vr" | "ar"}`) marche aussi dans la fenêtre d'activation
  qui suit un clic. `mode` : `vr`, `ar` ou `auto` (AR si l'appareil l'accepte, sinon VR). `reference` : `local-floor`
  (défaut ; repli automatique sur `local`) ou `local`. `features` (optionnelles, jamais exigées) : `hand-tracking`,
  `hit-test` (AR), `dom-overlay` (AR, avec `overlay` = id de l'élément montré par-dessus ; ses touchers ne
  sélectionnent rien dans la scène).
- **Pendant la session** : la boucle de rendu passe par `renderer.setAnimationLoop` (le `requestAnimationFrame` de la
  fenêtre ne tourne pas dans un casque) et celle de `sonic-3d` est suspendue, puis reprise à la sortie avec la caméra,
  l'orbite et la taille d'origine. Rendu direct scène + caméra : post-effets (`post-fx`), étalonnage et rendu photo
  sont coupés en XR. En AR, le fond (`scene.background`) est retiré puis restauré.
- **Placement** : une unité vaut un mètre. La scène est décalée pour que le centre de sa boîte englobante soit
  devant l'utilisateur à hauteur des yeux (1,4 m en `local-floor`) ; `offset="x y z"` (mètres) s'ajoute, `scale` la
  réduit ou l'agrandit (une maquette : `scale="0.2"`). En AR avec `hit-test`, l'état `hit` `{x, y, z}` donne le point du
  réel visé (coordonnées de la pièce), `reticle` y montre un anneau, la commande `place` y pose la scène (bas du centre
  de sa boîte).
- **Manettes, mains, toucher** : un `select` lance un rayon dans la scène, avec les mêmes filtres que le tap
  (`pick-names`, nœuds masqués ignorés). Il produit le même tap que `sonic-3d` (événement `pick`, action
  `pick-action-type` vers son `target` si `pick`, `instance` et `src` pour un objet d'un `monde`) et l'action
  `{type: "xr:select", payload: {objectId, instance?, src?, point, hand, mode, hit}}` vers `store` (`point` en
  coordonnées de la scène, `null` dans le vide).
- **État** `<id>State` : `{status, error, supported, allowed, active, mode, modes: {vr, ar}, presenting, reference, hit,
  inputs: [{handedness, mode, hand}]}` ; `modes` vient de `navigator.xr.isSessionSupported`, relu au montage.
  Événements DOM `sonic-xr-change`, `sonic-xr-select`, `sonic-xr-place`.
- **API pour d'autres composants** : `sonic-3d.getXrHost()` rend `{renderer, scene, camera, pause(), resume(), render(),
  bounds(), pickRay(origine, direction), tap(hit)}` (`null` tant que la scène n'est pas prête).

Limites : non testé sur casque ni sur téléphone (les tests simulent `navigator.xr`). Navigateurs visés : Meta Quest
Browser, Chrome Android (AR avec ARCore) ; pas Safari iOS. HTTPS obligatoire ; dans une iframe,
`allow="xr-spatial-tracking"` (fonctionnalité `xr-spatial-tracking` de la Permissions-Policy, lue dans `allowed`). Le
slot `selection` et les autres éléments HTML ne sont pas visibles dans un casque (seulement en AR avec `dom-overlay`).

### AR : une maquette posée devant soi

En AR, une scène à taille réelle (une pièce de 4 m) entourerait l'utilisateur et boucherait toute la vue de la caméra.
`sonic-xr` en fait donc une maquette : `ar-scale="auto"` (défaut) ramène son emprise au sol à 60 cm (un nombre impose
l'échelle), elle apparaît 90 cm devant soi à hauteur de table, les objets nommés dans `ar-hide` (défaut `plafond`) sont
masqués pour la voir de dessus. Le hit-test est toujours demandé : un anneau montre la surface visée (table, sol) et
toucher l'écran y pose la maquette. Chrome Android demande l'accès à la caméra à l'entrée en AR. La session AR occupe tout l'écran ; pour y garder des boutons (« Quitter »), `features="dom-overlay"` + `overlay="id"` : cet élément est affiché par-dessus la caméra (le montrer seulement quand `presenting` est vrai). Le contexte WebGL de `sonic-3d` a un canal alpha (effacé en opaque hors AR) : sans lui, la caméra restait cachée derrière un fond plein.

### Fenêtre magique (sans casque)

Pour tout le monde, iPhone compris et sans rien installer : la caméra se place au centre de la scène, à hauteur
des yeux (`eye`, 1,6 m, bornée par la hauteur de la scène), et suit les mouvements du téléphone (capteurs
d'orientation, permission demandée dans le clic sous iOS). Sans capteurs (ordinateur), glisser tourne la vue.
La vue passe en plein écran (sauf iPhone, qui le refuse hors vidéo : elle reste dans la page) ; Échap, la sortie du plein écran ou un nouveau clic la referme et rend la vue d'avant.

- Commande `magic` (bascule), ou `data-xr-mode="magic"` sur le bouton de `for`.
- Repli du clic : sans VR ni AR, le bouton de `for` ouvre la fenêtre magique (`fallback="magic"`, défaut ;
  `fallback="none"` pour l'empêcher).
- Plusieurs boutons pour un seul `sonic-xr` : `data-xr-mode="vr"`, `"ar"`, `"magic"` sur chacun (sinon `mode`).
- État : `modes.magic` (toujours vrai), `magic` (ouverte), `sensors` (les capteurs répondent).

```json
{ "tagName": "sonic-xr", "attributes": { "id": "casque", "target": "scene", "for": "btn-vr btn-ar btn-regard" } },
{ "tagName": "sonic-button", "attributes": { "id": "btn-regard", "data-xr-mode": "magic" }, "textContent": "Regarder autour" }
```

Tester la VR et l'AR sans casque : l'extension Chrome Immersive Web Emulator (Meta) simule un Quest
(boutons VR / AR, manettes dans l'onglet WebXR des outils de développement) ; l'AR réelle demande Chrome
Android sur un téléphone ARCore.
