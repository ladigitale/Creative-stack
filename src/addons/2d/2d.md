# Scène 2D / 2.5D (PixiJS)

Addon opt-in `@supersoniks/creative-stack/2d` (peer : `pixi.js`). `sonic-2d` rend une scène WebGL pilotée par données, **comme `sonic-3d`** : le mouvement arrive par la clé `nodes` de son DataProvider, au format partagé (`src/shared/nodes.ts`) que produisent `sonic-physics` (`nodes-plane="screen"`), un `sonic-store`, `sonic-timeline` (`nodes-out`) ou `sonic-p2p`.

## Qui fait quoi

| Rôle | Où |
|---|---|
| Déclarer les sprites (forme, couleur, texte, image, calque) | enfants `sonic-sprite`, ou liste en DataProvider (`sprites="jeu.decor"`) pour un nombre variable |
| Faire bouger | un producteur de `nodes` (physique, reducer, timeline, pair p2p) |
| Cadrer | la caméra `{x, y, zoom, ease}` : clé `camera` du DataProvider, ou attribut `camera="jeu.camera"` |
| Dessiner | `sonic-2d` (rendu à la demande : aucune boucle quand rien ne bouge) |
| Réagir à un tap | `target="jeu"` → `{type: "pick", payload: {objectId, x, y}}` (coordonnées du monde) |
| Boutons, textes d'interface hors scène | SDUI habituel (`sonic-action`, `sonic-value`) |

Un sprite ajouté (enfant ou élément de liste) reçoit aussitôt l'état de son nœud ; un nœud sans sprite est gardé et compté dans `missing`. Changer l'apparence d'un sprite le redessine sans le déplacer (comme un corps physique) : la position vivante vient de `nodes`, `x` / `y` / `angle` du sprite ne servent qu'au départ.

## Exemple

```json
{ "tagName": "sonic-physics", "attributes": { "id": "monde", "width": "1600", "height": "450", "hidden-preview": "", "nodes-plane": "screen", "input": "jeu.input" },
  "nodes": [ { "tagName": "sonic-body", "attributes": { "name": "b1", "r": "28", "x": "300", "y": "90" } } ] },
{ "tagName": "sonic-2d", "attributes": { "dataProvider": "mondeState", "camera": "jeu.camera", "width": "800", "height": "450",
    "layers": "ciel:0 montagnes:0.35 monde:1 hud:0", "target": "jeu", "pick-empty": "" },
  "nodes": [
    { "tagName": "sonic-sprite", "attributes": { "name": "soleil", "layer": "ciel", "r": "42", "x": "660", "y": "90", "fill": "#fde68a" } },
    { "tagName": "sonic-sprite", "attributes": { "name": "b1", "r": "28", "fill": "#f472b6" } },
    { "tagName": "sonic-sprite", "attributes": { "name": "aide", "layer": "hud", "text": "Touche une bille", "x": "400", "y": "22", "font-size": "16" } } ] }
```

Le monde physique (1 600 px) est plus large que la vue (800) : le reducer déplace la caméra (`{"camera": {"x": 900, "ease": {"ms": 700, "curve": "inOut"}}}`). Voir `examples/parallaxe.sdui.json` (billes, plateformes, montagnes en parallaxe, zoom).

## `sonic-2d`

| Attribut | Rôle |
|---|---|
| `dataProvider` | Clés `nodes` (mouvement) et `camera` (sinon celui d'un ancêtre) |
| `width`, `height` | Taille logique de la vue (800 × 450 par défaut) ; l'affichage prend la largeur disponible et garde les proportions |
| `background` | Couleur CSS ; vide ou `transparent` : fond transparent (la page se voit dessous) |
| `layers` | Calques du fond vers l'avant, `nom:parallaxe[:y]`. `1` suit la caméra (le monde), `0` reste fixe à l'écran (interface), entre les deux : décor lointain. `:y` trie les sprites par y (vue de 3/4, isométrique). Défaut : un calque `monde` |
| `camera` | Chemin DataProvider de la caméra (sinon clé `camera` du `dataProvider`) |
| `debug` | Contrôle visuel des maillages (`sprite shape="mesh"`) : `bones` (os de repos en gris, os courants colorés, articulations en jaune), `mesh` (quadrillage déformé ; chaque sommet est coloré selon l'os qui pèse le plus sur lui), `all`. Sert à voir si le squelette est bien posé sur l'image et si les poids sont cohérents | aucun |
| `sprites` | Chemin DataProvider d'une liste de sprites (≤ 500) |
| `target`, `pick-action-type`, `pick-names`, `pick-empty` | Taps vers un `sonic-store` (comme `sonic-3d`) |
| `out-data-provider` | Publie `{ status: loading \| ready \| error, error, count, missing, errors }` |
| `max-dpr` | Densité de pixels maximale (2) |

**Caméra** : `{ x, y, zoom, ease: { ms, curve } }`, point du monde au centre de l'écran (défaut : centre de la scène, zoom 1). Un calque de parallaxe `p` suit la caméra à `p` près et zoome de `1 + (zoom - 1) × p`.

## `sonic-sprite`

| Attribut | Rôle |
|---|---|
| `name` | Nom du nœud (`nodes`), du corps physique de même nom, des taps |
| `shape` | `box` (`w` `h` `radius`), `circle` (`r`), `polygon` (`points` relatifs au centre), `text` (`text` `font-size` `font`), `image` (`src` ou `source`, `w` `h`), `mesh` (image déformable : `src` ou `source`, `w` `h`, `grid` `influences` `falloff` `skin-bones`) |
| `fill` `stroke` `line` | Couleurs et contour (même vocabulaire que `sonic-body`) |
| `blend` | Fusion avec le dessous : `normal` (défaut), `add`, `screen`, `multiply`. Avec `screen`, un `sonic-shader` de fumée (gris sur noir, `source="#fumee"`) devient une brume transparente |
| `x` `y` `angle` | Position et angle (°) de départ |
| `pivot` | Point `x,y` du sprite (part de sa largeur et de sa hauteur depuis le coin haut-gauche) placé sur la position du nœud et centre de sa rotation : `0.5,0.5` (centre, défaut), `0.5,0` (haut-centre : épaule d'un bras pendant). Sans effet sur `polygon`. À employer avec `sonic-skeleton` (addon `animation`), qui écrit des `nodes` par os |
| `grid` `influences` `falloff` `skin-bones` | `mesh` seulement : maille `colonnes,lignes` (2 à 40, défaut `8,8`), os qui influencent un sommet (1 à 4, défaut 3), exposant de la décroissance des poids avec la distance (défaut 2 ; grand = jonctions plus nettes), os liés (noms séparés par des virgules ; vide = tous) |
| `opacity` `layer` `z` `hidden` | Opacité, calque (`monde` par défaut), ordre dans le calque, caché au départ |
| `blend` | Fusion avec ce qui est dessous : `normal` (défaut), `add`, `screen` (fumée, lumière : un `sonic-shader` noir en `source` devient transparent), `multiply` (ombre) |

`src` : image `data:image/…;base64,…` ou URL `https://`. `source="#id"` : image **vivante** d'une source d'images (`getFrameCanvas` + `frameSeq` : `sonic-camera`, `sonic-mask-replace`, `sonic-frame-sync`…), redessinée à chaque nouvelle image ; l'image tient dans `w` × `h`, proportions conservées. Avec `sonic-mask-replace effect="cutout"`, c'est la personne (ou un objet) découpée, à recomposer avec les calques et `nodes` (`vision/examples/recomposition.sdui.json`). Tant qu'un sprite `source` existe, la scène redessine en continu (plus de rendu à la demande). Pour une page sans réseau, préférer les formes, le texte et les emoji.

### Maillage déformable (`shape="mesh"`)

Une image qui **se plie entre les os** d'un `sonic-skeleton` (addon `animation`) au lieu de tourner d'un bloc : bras, queue, tentacule, personne découpée. Le sprite lit `rest` (pose de repos) et `bones` (pose courante) du même DataProvider que `nodes` (`<nodes-out>.rest` / `.bones`, écrits par le squelette). On dessine l'image **dans la pose de repos**, centrée sur `x` `y` (taille `w` × `h`, étirée : pas de proportions conservées) ; chaque sommet de la grille se lie aux `influences` os les plus proches (poids décroissants avec la distance au segment de l'os) et suit leur mélange : loin d'une articulation il suit un seul os (rigide), près d'elle les deux (la pliure se lisse). `src` ou `source="#id"` comme `image`.

- Les sommets sont déjà placés dans la scène : **ne pas** donner au sprite un nœud de même nom qu'un os (ça décalerait tout le maillage). Un nœud de son propre nom le déplace, le tourne ou le masque en bloc.
- Un os de `rest` peut porter `radius` (demi-largeur, unités de la scène ; publié par `sonic-puppet`) : les poids viennent alors de la distance à la **surface** de l'os (négative à l'intérieur) et non à son axe, et `falloff` règle la largeur du mélange (grand = jonctions plus nettes). Un os large, comme un tronc, revendique tout son intérieur : un bras le long du corps ne tire plus le flanc.
- `pivot` est ignoré (le maillage est dessiné à sa position de repos).
- `skin-bones="bras,avant-bras"` limite les os qui déforment cette image (plusieurs maillages, un par membre, peuvent se partager un squelette).
- Plus de mailles et plus d'influences : pliure plus fine mais plus de calcul (jusqu'à 41 × 41 sommets, calculés à chaque pose). `falloff` petit : pli très doux ; grand : presque rigide par morceaux.
- Sans squelette (ou aucun os valide), le sprite s'affiche comme une image plate à sa position.
- Exemple : `animation/examples/bras-souple.sdui.json`.

## Format `nodes`

Le même que `sonic-3d` et `sonic-stage` : `{ "nom": { x, y, rz, scale, opacity, visible, z, color, ease } }`, `rz` en radians, sémantique patch, `"$reset": true` remet chaque sprite à sa description. `color` redessine le sprite avec cette couleur.

## Règles

1. Un sprite par nom ; une liste (`sprites`) ne peut pas reprendre le nom d'un enfant `sonic-sprite`.
2. Le mouvement vient de `nodes`, jamais d'un changement de `x` / `y` du sprite.
3. Interface fixe (score, aide) : un calque à parallaxe `0`, ou du SDUI au-dessus de la scène.
4. Pas de WebGL : `status: "error"` et un message à la place de la scène.

## Ressources de base

`src/addons/2d/library/` (indexées dans `dist/library.json`, ids `2d/…`) : `jeu-de-cartes-52` (données : rang, valeur, couleur, symbole, label), `palettes-couleurs` (8 palettes de 5 couleurs hex), `motif-points` et `motif-vagues` (fonds SVG sans script ni ressource externe, à retailler). À utiliser avant d'en recréer.

## Lire la scène comme texture

`sonic-2d` est une source d'images (`getFrameCanvas` + `frameSeq`, comme `sonic-3d`) : `sonic-shader channel0="#scene"` lit la scène rendue (sprites, calques, caméra, `blend`), pour un post-traitement (grain, flou de profondeur, étalonnage). Le canvas est conservé après chaque rendu (`preserveDrawingBuffer`). Attention : un effet qui se sert d'une carte de profondeur **fixe** (photo) sur une scène animée se décale dès que le sujet bouge ; réserver la profondeur aux éléments immobiles (le fond) et animer les autres par calques de parallaxe.

## La scène comme texture

`sonic-2d` est une source d'images (`getFrameCanvas` + `frameSeq`, comme `sonic-3d`) : `sonic-shader channel0="#scene"` lit le rendu complet (calques, caméra, maillages, fusions) et peut lui appliquer un post-traitement (grain, étalonnage, lueur). Attention : un shader qui déforme l'image selon une profondeur ne suit pas un sujet animé ; réserver ce genre d'effet à un décor figé (calque à part).
